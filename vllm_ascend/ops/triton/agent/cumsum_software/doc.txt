❯ 你grid优化了什么                                                              

● Grid 优化改的是 _compute_optimal_block_t 函数，核心变化是 BLOCK_T 的选择策略：

  优化前（第一版）：从大到小缩减 BLOCK_T，确保 blocks >= core_num。对于 B=1,
  T≈6986, H=8 的典型场景，选出 BLOCK_T=128，产生 55 个 blocks。40 个核心需要跑 2
   波（第一波 40 blocks，第二波 15 blocks），第二波只用了 37.5%
  的核心，且多了一次波调度开销。

  优化后（当前版本）：反过来，优先选择 blocks <= core_num 的
  BLOCK_T（单波执行）。同样场景下选出 BLOCK_T=256，产生 28 个
  blocks，一波跑完，70% 核心利用率，零调度开销。

  实测效果（msprof 数据）：
  - Kernel 平均耗时：7.728us → 5.004us（1.54x 加速）
  - MTE3 等待占比：17-35% → 4-5%（BLOCK_T 更大，每 block
  数据量更多，写回等待相对占比下降）
  - Block Dim：55 → 28

  选择逻辑就是：在满足 UB 容量（192KB）和 power-of-2 约束的前提下，枚举所有合法
  BLOCK_T，挑出能单波执行且核心利用率最高的那个。如果没有任何 BLOCK_T
  能单波，就退回到最大合法 BLOCK_T 来最小化波数。
