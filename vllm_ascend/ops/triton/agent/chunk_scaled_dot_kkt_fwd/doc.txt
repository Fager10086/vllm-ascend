  优化技术清单

  1. [已应用] 固定 1D Grid + Stride Loop：将 Grid 从数据相关的 (NT, 1)
  转换为固定的 (get_vectorcore_num() // 2, ) = 20 核，满足 Ascend NPU Grid
  规范要求
  2. [已应用] B×H 维度并行化：将 kernel 内串行的 for i_bh in range(B * H)
  循环（64次迭代）展开到 Grid work items 中，total_blocks = B * H * NT = 2 * 32 
  * 16 = 1024，每个 work item 处理一个 (batch, head, chunk) 组合
  3. [已应用] NT 声明为 tl.constexpr：使 work_idx // NT 和 work_idx % NT
  的除法/取模操作可被编译器优化为移位/掩码操作，减少 Scalar 开销
  4. [已应用] 消除 @triton.heuristics：移除 IS_VARLEN 和 USE_G 的 heuristics
  装饰器，改为显式传参，减少 host 侧开销
  5. [已应用] do_not_specialize 避免重编译：对 T、B、total_blocks
  等运行时可变标量使用 do_not_specialize，避免不同输入形状触发重编译
  6. [未应用] Transpose 消除：尝试消除 host 侧 permute().contiguous()
  预处理，但因非连续 stride 访问导致 UB overflow（需 8421376 bits，仅有 1572864
  bits 可用），无法实现
  7. [未应用] 显式指针替换 make_block_ptr：尝试用 tl.arange 显式指针 + mask 替换
   make_block_ptr，但 tl.load(other=0.0) 触发内部 tl.where，阻塞 MTE
  流水线，导致严重性能回退（81us → 219us）

  关键修改说明

  - 修改点 1：Grid 从 (triton.cdiv(T, BT), 1) 改为 (get_vectorcore_num() // 2, 
  )，kernel 入口添加 pid = tl.program_id(0); num_programs = tl.num_programs(0)
  和 stride loop for work_idx in range(pid, total_blocks, num_programs)
  - 修改点 2：非 varlen 路径中，将 work_idx 解码为 i_bh = work_idx // NT; i_t = 
  work_idx % NT; i_b = i_bh // H; i_h = i_bh % H，替代原来的串行 for i_bh 循环
  - 修改点 3：Host 函数中 total_blocks = B * H * NT（非 varlen）或
  len(chunk_indices)（varlen），传入 kernel 作为动态参数
  - 修改点 4：Varlen 路径保留 for i_bh in range(B * H) 内循环（因 chunk_indices
  已包含序列信息，无需额外并行化维度）
  - 修改点 5：保留 make_block_ptr + boundary_check 模式和 host 侧
  permute().contiguous() 预处理，这是 Ascend NPU 上性能最优的访存方式
