● 以下是本次 cumsum 算子优化过程中所应用的全部优化点：

  ---
  优化点总结

  1. 消除冗余 transpose（Kernel 内）

  基线代码：reshape → tl.trans → tl.cumsum(axis=0) → tl.trans → reshape，在
  cumsum 前后各做一次 transpose。

  优化后：reshape → tl.cumsum(axis=1 或 axis=2) → reshape，通过指定正确的 axis
  参数直接在目标维度上执行 cumsum，完全消除两次 tl.trans。

  原理：tl.trans 在 UB 内产生数据搬移，消耗 Vector 周期且增加 UB
  峰值占用。tl.cumsum、tl.sum 等规约操作本身支持 axis
  参数，可以直接选择任意维度，无需先 transpose 到 axis=0。

  实测效果：Task Duration 从 4.231us 降至 3.806us（-10.1%）。

  ---
  2. 2D Grid 转 1D 固定 Grid + stride loop（Kernel + Host）

  基线代码：grid = (num_blocks, B)，Grid 大小依赖输入数据形状，kernel 内通过
  tl.program_id(0) 和 tl.program_id(1) 分别获取 block 和 batch 索引。

  优化后：grid = (get_vectorcore_num(), )，固定为 NPU 物理核心数。kernel 内通过
  stride loop for work_idx in range(pid, total_blocks, num_programs)
  遍历所有工作块，每次迭代内部通过整数除法/取模解码出原始的 i_b 和 i_block。

  原理：规范要求 Grid 大小禁止与输入形状关联，必须使用固定大小，确保泛化性。host
   侧新增 total_blocks = B * num_blocks（非 varlen）或
  len(block_indices)（varlen），以及 blocks_per_batch 参数传入 kernel。

  代码变更：
  - kernel 签名：删除 B: tl.constexpr，新增 total_blocks 和 blocks_per_batch
  作为动态参数
  - kernel 体：删除 i_block, i_b = tl.program_id(0), tl.program_id(1)，新增 pid 
  = tl.program_id(0) + num_programs = tl.num_programs(0) + stride loop
  - host 侧：grid = (num_blocks, B) → grid = (get_vectorcore_num(), )

  ---
  3. do_not_specialize 避免重编译（Kernel 装饰器）

  基线代码：@triton.jit(do_not_specialize=["T"])，仅对 T 关闭特化。

  优化后：@triton.jit(do_not_specialize=["T", "total_blocks", 
  "blocks_per_batch"])，对所有运行时可能变化的标量参数关闭特化。

  原理：Triton 默认对每个标量参数值生成独立的编译版本。当 total_blocks 和
  blocks_per_batch 随输入序列长度变化时，如果不加
  do_not_specialize，每次变化都会触发重编译（秒级开销），严重影响推理性能。

  ---
  4. 删除 num_warps / num_stages 参数（Host 侧）

  基线代码：kernel 启动时传入 num_warps=8, num_stages=3。

  优化后：删除这两个参数，使用 Triton 编译器默认值。

  原理：num_warps 和 num_stages 是 GPU 概念（warp 调度、软件流水级数），在昇腾
  NPU 上无实际意义，NPU 编译器会忽略这些参数。删除后减少不必要的参数传递。

  ---
  5. 变量命名规范化（Kernel 内）

  基线代码：varlen 路径中直接复用 T = eos - bos 覆盖入参 T，且 make_block_ptr
  中使用被覆盖后的 T。

  优化后：使用独立变量 cur_T = eos - bos，make_block_ptr 中使用 cur_T，入参 T
  保持不变。

  原理：避免在 varlen 和非 varlen 分支中同名变量语义不一致的问题。非 varlen 路径
   cur_T = T 语义清晰，varlen 路径 cur_T = eos - bos 表示当前序列的实际长度。

  ---
  6. BLOCK_T 动态适配 UB 容量（Host 侧）

  基线和优化后均使用：OPTIM_BLOCK_SIZE = triton.next_power_of_2((2**18) // (H * 
  chunk_size))。

  原理：BLOCK_T 根据 H 和 chunk_size 动态计算，使得单次 load 的数据量尽量填满 UB
   可用空间。对于 H=8, chunk_size=64，计算得 BLOCK_T=512，对应单次 load 占用 =
  512 × 8 × 4B = 16KB（float32），cumsum 中间变量同样 16KB，总 UB 峰值约
  32KB，在 85KB 限制内。
